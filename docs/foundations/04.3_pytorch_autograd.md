# PyTorch Autograd and NN2LLM

# Overview

PyTorch autograd is a reverse-mode automatic-differentiation system. It
records differentiable tensor operations during a forward pass, then applies
the chain rule backward from an output to compute gradients. NN2LLM will build
the same fundamental mechanism in a small, inspectable `Value` class.

# Learning Objectives

After this chapter, you should be able to:

- Explain what automatic differentiation computes.
- Identify the role of `requires_grad`, `grad_fn`, and `.grad` in PyTorch.
- Explain why `loss.backward()` starts at the output.
- Relate a PyTorch backward pass to NN2LLM's future `Value.backward()`.

# Theory

Automatic differentiation is neither symbolic differentiation nor numerical
finite differences. It decomposes a program into elementary operations, uses
the exact derivative of each operation, and combines them with the chain rule.

Reverse mode is especially useful when there are many parameters but one
scalar loss: one backward traversal computes the loss derivative with respect
to every participating parameter.

# Intuition

Imagine a relay race. In the forward pass, each runner hands a value to the
next runner. In the backward pass, the final runner sends back information
about how sensitive the final result was. Each runner uses a local rule to
pass the appropriate sensitivity to earlier runners.

# Mathematics

For:

```text
y = a * b
loss = y + c
```

The local derivatives are `d(y)/d(a) = b`, `d(y)/d(b) = a`, and
`d(loss)/d(y) = 1`. The chain rule gives:

```text
d(loss)/d(a) = 1 * b
d(loss)/d(b) = 1 * a
```

The backward pass starts by setting the output gradient to one because a
quantity changes one-for-one with itself.

# Computer Science Perspective

PyTorch stores operation history as a dynamic graph. Tensors created by
differentiable operations have a `grad_fn` that represents how they were
produced. Leaf tensors created by the user can request gradients with
`requires_grad=True`; after backward propagation, their accumulated gradients
are available through `.grad`.

The graph is released after backward by default to save memory. Applications
that genuinely need to traverse the same graph again can request retention,
but retaining graphs unnecessarily increases memory use.

# Deep Learning Perspective

A training step commonly follows this sequence:

```python
prediction = model(features)
loss = criterion(prediction, target)
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

`zero_grad()` is important because PyTorch accumulates gradients into parameter
buffers. Accumulation is useful for some training strategies, but ordinary
iterations must clear old gradients before computing new ones.

# Engineering Perspective

Autograd systems need four pieces of information:

1. The forward numerical result.
2. Parent dependencies.
3. A local backward rule for each operation.
4. A reverse dependency-aware traversal order.

They also need careful memory management at tensor scale. NN2LLM deliberately
starts without these optimizations so the differentiation logic stays clear.

# Connection to NN2LLM

`Value.data` corresponds to a tensor's numerical value. `Value.parents` and
`Value.operation` describe the graph relation. The current `_backward`
placeholder will become a callable local-gradient rule. A future
`Value.backward()` will build a topological order, set the output gradient to
`1.0`, and call local rules in reverse order.

Unlike PyTorch, the first NN2LLM version will operate on scalar values. This
is intentional: the chain rule is identical for tensors, while scalar nodes
make every contribution easy to inspect.

# Interview Questions

## What does autograd compute?

It computes derivatives of an output with respect to graph inputs by applying
the chain rule to recorded operations.

## Why does `loss.backward()` begin with a gradient of one?

The derivative of the scalar loss with respect to itself is one.

## Why are gradients cleared before a new training step?

Gradient buffers accumulate by default, so old values would otherwise mix with
the new batch's gradients.

# Common Misconceptions

- Autograd is not numerical approximation; it uses exact local derivatives.
- `.grad` is generally populated for leaf tensors, not every intermediate
  tensor.
- `backward()` computes gradients; it does not update parameters by itself.

# Key Takeaways

- PyTorch builds a dynamic computation graph during the forward pass.
- Reverse-mode automatic differentiation efficiently differentiates one loss
  with respect to many parameters.
- Local derivative rules, graph structure, and reverse traversal form the
  core of autograd.
- NN2LLM is ready to implement DFS, topological sort, and local backward
  rules from first principles.
