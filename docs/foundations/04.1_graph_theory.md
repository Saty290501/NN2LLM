# Graph Theory for Computational Graphs

# Overview

Graph theory gives us a precise way to describe the relationships created by
an expression. In NN2LLM, every `Value` object is a node and every parent
reference is a dependency edge. This chapter introduces the graph ideas that
make traversal, automatic differentiation, and backpropagation possible.

# Learning Objectives

After this chapter, you should be able to:

- Define nodes, edges, paths, and directed graphs.
- Explain why a computational graph is a directed acyclic graph (DAG).
- Distinguish a graph from a tree when inputs are reused.
- Explain why a visited set is necessary during graph traversal.

# Theory

A graph is a pair `G = (V, E)`, where `V` is a set of vertices (nodes) and
`E` is a set of edges connecting them. A directed edge has an orientation:
`u -> v` means that `v` depends on `u`.

For `output = (a * b) + c`, the graph has input nodes `a`, `b`, and `c`, an
intermediate multiplication node, and an output addition node. Edges point
from inputs toward the values they create.

A path is an ordered sequence of edges. If there is a path from a parameter
to a loss, changing that parameter can affect the loss.

# Intuition

Think of a graph as a recipe with reusable ingredients. If `a` appears in two
parts of an expression, there is still only one `a` node; both operations
refer to it. A tree drawing may show `a` twice to make branches easier to see,
but the underlying object graph has one shared node.

# Mathematics

Consider:

```text
y = (a * b) + (a + b)
```

The same variables are used in two subexpressions. Its graph contains the
edges `a -> a*b`, `b -> a*b`, `a -> a+b`, `b -> a+b`, and both intermediate
nodes point to `y`.

This sharing matters later because `dy/da` receives a contribution from every
path between `a` and `y`.

# Computer Science Perspective

A computational graph is a DAG:

- **Directed:** edges represent dependency order.
- **Acyclic:** no node can eventually depend on itself.

A cycle would make an ordinary forward computation impossible: computing `a`
would require a value that ultimately requires `a` again. DAGs can be ordered
so every dependency is processed before the value that needs it. This is a
topological order.

Depth-first search (DFS) explores one dependency branch fully before moving
to another. DFS needs a `visited` set because the same input may be shared by
several branches. The set prevents duplicate work and, in a general graph,
prevents infinite recursion through cycles.

# Deep Learning Perspective

A neural network forward pass creates a large DAG. Input features and model
parameters feed into operations, operations produce activations, and the final
loss sits at the output. The graph captures exactly which parameters
contributed to that loss.

# Engineering Perspective

NN2LLM stores graph structure locally: `Value.parents` holds the immediate
dependencies and `Value.operation` records how a node was created. This avoids
a separate global graph object while retaining enough information for graph
utilities such as `trace` and future DFS and topological-sort functions.

# Connection to NN2LLM

For a `Value` instance, `parents` is the outgoing dependency information when
we traverse from an output back toward its inputs. `trace(root)` already walks
this relationship to collect nodes and edges. The next implementation will
expose DFS explicitly so its order can be inspected and tested.

# Interview Questions

## Why is a computational graph a DAG?

Each result depends only on values already created during the forward pass, so
dependencies have a direction and cannot form a loop.

## Why is a computational graph not always a tree?

One input or intermediate result can be reused by multiple later operations.
A tree cannot represent that shared node without duplicating it.

## Why use a visited set in DFS?

It ensures shared nodes are processed once and protects the traversal from
revisiting a node.

# Common Misconceptions

- A graph node is not necessarily an operation; in NN2LLM it is a `Value`.
- A tree-shaped visualization does not prove the underlying structure is a
  tree.
- A DAG does not mean each node has only one parent or only one child.

# Key Takeaways

- Graphs model dependencies between values.
- Computational graphs are directed acyclic graphs.
- Shared values make them graphs rather than simple trees.
- DFS and topological ordering are essential preparation for backpropagation.
